使用说明：先将下方 WORKSPACE_ROOT 改成你自己的绝对路径（例如 D:\WorkSpace），再将正文交给 Codex。已有工作区请先核对现有文件和规则。此文件为工作站初始化模板。

# Codex WorkSpace 
请为本机建立一套长期使用的 Codex 项目工作体系。

---

# 0. 工作区位置

本机唯一长期工作区设为：

`WORKSPACE_ROOT = <替换为你自己的绝对路径>`

如果我要使用其他位置，我会在执行本提示词前修改这一行。

以下所有 `WorkSpace` 均指 `WORKSPACE_ROOT`。

不要自行创建第二个 WorkSpace。

---

# 1. 总体目标

建立一套：

* 项目隔离；
* Agent 交接；
* 长期经验沉淀；
* Skills 管理；
* 最小项目初始化；
* 低 Token 消耗；

的 Codex 工作体系。

核心原则：

> 短规则直接读取，长知识按需搜索。

> 创建项目只建立容器，不自动规划或执行项目。

> 用户后续具体任务驱动项目逐步生长。

> Codex 可以发现和推荐新 Skill，但是否安装、升级、删除或提升范围由用户决定。

---

# 2. 初始化 WorkSpace

如果工作区不存在则创建；如果已经存在，先读取现有内容，不覆盖有效文件。

建立：

```text
WorkSpace\
├── AGENTS.md
├── 00_全局控制台.md
├── 01_全局复盘与踩坑日志.md
├── 02_新项目创建SOP.md
├── 03_Skills管理与索引.md
├── skills\
└── projects\
```

不要额外创建：

* 总路线图；
* 总 TODO；
* 总启动清单；
* Memory Summary；
* Archive；
* 额外索引；
* 其他没有明确需要的管理文件。

---

# 3. Codex 全局 AGENTS

找到本机真实 Codex Home。

如果存在：

`~/.codex/AGENTS.md`

先读取并保留已有有效规则。

加入一个简短的 `WorkSpace Core Rules`。

只写以下级别规则：

1. 唯一项目工作区是 `WORKSPACE_ROOT`。
2. 所有项目进入 `WorkSpace\projects\project-XXX-name`。
3. 已有项目启动顺序：
   `项目 AGENTS.md → 00_项目入口.md → 01_项目总览.md`。
4. 长日志和知识库先搜索，再局部读取。
5. 新项目创建只做最小初始化。
6. 新 Skill 的安装、升级、删除、替换、范围提升必须经用户明确同意。
7. 项目经验按：
   `项目日志 → 全局复盘 → 全局控制台`
   逐层提炼。
8. 不无理由修改其他项目。

不要把完整 SOP 或 Skill 清单复制进 Codex 全局 AGENTS。

---

# 4. WorkSpace AGENTS.md

这是整个 WorkSpace 的短规则入口。

保持简短，只负责：

* 工作区位置；
* 项目启动顺序；
* 各全局文件何时读取；
* 新项目最小初始化；
* Skill 权限边界；
* 项目隔离；
* Agent 交接；
* 经验蒸馏；
* 新项目加入 Codex 项目列表的要求。

## 读取原则

已有项目：

```text
项目 AGENTS.md
↓
00_项目入口.md
↓
01_项目总览.md
↓
继续当前任务
```

遇到历史问题时再搜索：

`02_问题与报错日志.md`

必要时再搜索：

`01_全局复盘与踩坑日志.md`

普通项目启动：

* 不读取新项目 SOP；
* 不扫描全部 Skills；
* 不扫描整个 WorkSpace。

# 5. 五个全局文件职责

## `AGENTS.md`

只做：

**路由和最高级执行边界。**

---

## `00_全局控制台.md`

只保存：

* 最高价值原则；
* 跨项目最通用规则；
* 最容易造成严重返工的问题；
* 已经多次验证的核心经验。

不要保存详细案例。

---

## `01_全局复盘与踩坑日志.md`

保存：

**跨项目可复用或 WorkSpace 全局管理层面的经验。**

项目详细错误仍留在项目自身日志。

条目优先压缩为：

```text
问题 / 触发条件
→ 根因
→ 已验证解决原则
→ 防复发
```

新增前先搜索，优先合并，不重复追加。

---

## `02_新项目创建SOP.md`

只负责：

**新项目如何创建。**

创建项目与规划/执行项目严格分离。

---

## `03_Skills管理与索引.md`

只负责：

**主要 Skill 的轻量索引和权限规则。**

普通启动和单纯创建项目不读取此文件。

# 6. 五文件 Token / 字符预算

统一以：

**源文本去除空白后的 Unicode 可见字符**

作为维护指标。

标点、英文、路径、Markdown 标记都计入。

这不是 Token 精确值，只作为控制长期文档体积的稳定指标。

预算：

| 文件                |        目标 |  硬上限 |
| ----------------- | --------: | ---: |
| AGENTS.md         |  800～1000 | 1200 |
| 00_全局控制台.md       |  600～1000 | 1200 |
| 01_全局复盘与踩坑日志.md   | 1500～2000 | 2500 |
| 02_新项目创建SOP.md    | 1500～1800 | 2200 |
| 03_Skills管理与索引.md | 1500～2000 | 2500 |

五文件：

* 目标总量：6000～8000
* 硬上限：10000

经验不足时允许明显低于目标。

不要为了凑字数制造规则或经验。

五文件达到约 9000，或者任一文件接近硬上限：

执行轻量蒸馏：

1. 删除重复；
2. 合并近义规则；
3. 删除可以重新查询的环境细节；
4. 淘汰失效信息；
5. 长案例压缩为原则。

不得通过删除用户核心约束来达到字数要求。

# 7. 新项目命名

所有项目位于：

`WorkSpace\projects\`

格式：

`project-XXX-name`

例如：

```text
project-001-data-analysis
project-002-paper-writing
project-003-gcms-pops
```

规则：

* XXX 为三位编号；
* 从 001 开始；
* 新编号不复用已经使用过的历史编号；
* 删除项目也不降低编号高水位；
* 新建前检查实际一级项目目录以及历史最大编号；
* 项目名称简短、稳定。

SOP 中只维护：

```text
历史已使用最大编号：
当前下一个编号：
```

不要把 SOP 变成历史项目数据库。

# 8. 新项目必须采用“最小初始化”

用户只说：

> 新建 XXX 项目

或者：

> 新建 XXX 项目，目标是 XXX

时：

这只代表：

**创建项目。**

不代表：

* 开始研究；
* 拆解路线；
* 做分析计划；
* 做文献计划；
* 做 Skill 规划；
* 创建任务树；
* 开始执行长期目标。

# 9. 新项目只创建四个核心文件

后续具体任务实际需要什么，再创建什么。

# 11. 新项目创建时禁止的行为

单纯创建项目时：

禁止：

* Skill Discovery；
* Skills 使用计划；
* 路线图；
* 启动信息清单；
* README；
* TODO；
* milestone；
* workflow plan；
* research plan；
* 数据分析计划；
* 文献计划；
* 论文计划；
* 主动研究项目主题。

也不要因为项目长期目标复杂就询问：

* 样本量；
* 仪器型号；
* 软件；
* 数据格式；
* 目标期刊；
* 统计方法；
* 研究问题；
* 时间节点。

这些信息等具体任务真正需要时再处理。

---

# 12. 新项目加入 Codex 项目列表

新项目文件创建完成后：

自动尝试将项目目录添加到 Codex 左侧项目列表。

该动作已获得用户长期授权，不需要每次再次询问。

必须区分：

```text
文件夹创建成功
```

和：

```text
Codex 项目列表登记成功
```

两者分别核验。

如果当前版本或当前工具无法自动添加：

如实报告：

> 项目文件已创建，但 Codex 左侧项目列表尚未同步。

然后给出最少必要手动步骤。

不得伪造同步成功。

不得为了同步侧栏而额外创建 Git 仓库、任务或工作树。

---

# 13. 后续项目自然生长

项目建立后：

**用户问到哪里，项目就生长到哪里。**

例如：

用户明确开始处理数据：

才创建 `data`、`scripts` 等实际需要目录。

用户要求生成最终成果：

再创建 `outputs`。

用户要求设计研究方案：

再建立研究方案文档。

用户要求论文规划：

再建立论文相关内容。

不要提前预建。

---

# 14. Agent 交接

Agent 交接主要依靠：

`01_项目总览.md`

以下情况需要更新项目总览：

* 完成明显阶段；
* 当前会话准备结束；
* 准备切换工作阶段；
* 当前上下文已经很长；
* 项目阻塞；
* 关键方案变化；
* 新 Agent 准备接手。

项目真实开工后，总览逐渐维护：

* 项目目标；
* 当前状态；
* 已完成；
* 当前正在进行；
* 下一步；
* 未解决问题；
* 关键决策；
* 关键文件；
* 环境与依赖；
* 最近更新时间。

总览保持：

**最新状态快照**

而不是每日流水账。

新的 Agent 接手时：

优先从总览继续，而不是重新扫描项目。

# 15. 项目错误记录

有真实价值的问题记录到：

`02_问题与报错日志.md`

优先记录：

```text
触发条件与影响
失败尝试
已验证根因
解决方案与验证
预防复发
相关文件 / 状态
```

不记录：

* 普通控制台输出；
* 一次性拼写错误；
* 没有未来价值的小错误。

---

# 16. 经验向上蒸馏

知识流：

```text
项目问题日志
↓
全局复盘
↓
全局控制台
```

项目中的具体案例进入全局前：

必须去项目化、去重、抽象。

只有最高价值、最高复用、最容易造成严重返工的经验：

才进一步进入：

`00_全局控制台.md`

# 17. Skills 管理

Skills 遵循：

> 优先已有能力，最少必要安装。

单纯创建项目：

**不进行 Skill Discovery。**

只有用户提出具体任务，而且该任务确实可能需要 Skill 时：

才检查已有能力。

---

# 18. 缺少 Skill 时

如果已有 Skill：

直接按需使用。

如果当前任务确实缺少新 Skill：

在安装前告诉用户：

1. Skill 名称；
2. 主要功能；
3. 为什么当前任务需要；
4. 必要 / 推荐 / 可选；
5. 不安装有什么影响；
6. 建议项目级还是全局；
7. 来源；
8. 主要权限或风险。

然后等待用户决定。

未经明确同意不得：

* 安装；
* 升级；
* 删除；
* 替换；
* 修改 Skill 发现链接；
* 将项目 Skill 提升为全局 Skill。

---

# 19. Skills 索引保持轻量

`03_Skills管理与索引.md`

默认只保存：

* 名称；
* 类型/范围；
* 一句话用途；
* 来源；
* 状态。

只有 Skill 实际被项目调用以后：

才记录简短的真实使用项目。

禁止记录：

* 计划使用；
* 候选使用；
* 根据长期目标预测的 Skill 绑定。

也不要长期复制：

* 超长安装路径；
* cache 路径；
* 完整版本链；
* 大量重复权限描述。

这些需要时现场查询。

# 20. Skills 分类

采用：

```text
系统已有
↓
用户级全局
↓
项目专用
```

用户长期维护的自有通用 Skill 源文件可以放：

`WorkSpace\skills\`

项目专用 Skill 留在对应项目。

只有经过多个真实项目验证以后：

Codex 可以建议提升为全局 Skill。

最终决定仍属于用户。

---

# 21. 项目隔离

项目 A 默认不得修改项目 B。

跨项目复用时：

优先明确形成：

* 通用 Skill；
* 共享模板；
* 共享组件；

不要建立隐式跨项目依赖。

---

# 22. 文件创建原则

文件和目录：

**实际需要时才创建。**

如果后续确实需要：

临时文件优先放项目 `tmp`。

最终交付物优先放项目 `outputs`。

不得擅自删除原始数据。

---

# 23. 每次实质任务完成后的轻量检查

只检查：

### 项目状态是否变化？

是 → 更新项目总览。

### 出现值得复用的问题？

是 → 写项目问题日志。

### 具有跨项目价值？

是 → 提炼到全局复盘。

### 已经成为最高级原则？

是 → 提炼到全局控制台。

### 实际 Skill 使用状态变化？

是 → 更新 Skills 索引。

如果均没有：

**什么都不要额外写。**

---

# 24. 初始化时不要虚构历史

这是新电脑。

除非发现 WorkSpace 中确实已有历史文件：

否则：

* 全局复盘初始可以为空；
* Skills 使用项目可以为空；
* 项目编号从实际目录判断；
* 不虚构历史问题；
* 不虚构 Skill 使用；
* 不虚构 Agent 交接；
* 不为了填满模板制造内容。

---

# 25. 初始化完成后自检

完成后检查：

1. WorkSpace 路径正确；
2. 7 个基础文件/目录存在；
3. Codex 全局 AGENTS 已建立 WorkSpace 路由；
4. 没有额外创建项目；
5. 没有自动安装 Skill；
6. 没有创建多余管理文档；
7. 五个全局文件字符数符合预算；
8. 当前下一个项目编号正确。

最后报告：

```text
WorkSpace 路径：
Codex Home：
下一个项目编号：

AGENTS.md：
00_全局控制台.md：
01_全局复盘与踩坑日志.md：
02_新项目创建SOP.md：
03_Skills管理与索引.md：
五文件合计：

检测到的主要 Skills：
需要用户决定的事项：
```

如果修改了 Codex Home 下的全局 AGENTS：

提醒用户新开 Codex 会话，让新的全局规则重新加载。

---

# 最终原则

整个体系长期遵守：

> 创建项目只建立容器。

> 具体任务驱动项目生长。

> Agent 通过项目总览持续交接。

> 长知识按需搜索。

> 真实问题逐层蒸馏。

> Skill 只在具体任务需要时检查。

> 新 Skill 与重要权限变化由用户决定。

> WorkSpace 管理体系本身必须保持轻量，不能成为明显的 Token 负担。

现在开始初始化本机 WorkSpace。
